# Offline RC-002 Transport Rehearsal / 离线执行切片

**Implemented engineering tooling, not a model experiment, accepted case, scoring contract, or leaderboard.** Authorization: [ADR-0005](../decisions/ADR-0005-offline-pilot-tooling.md). Python 3.10+ and Git for repository checks; no dependencies to install.

## 直接运行 / Run

在 repo root 运行；`experiments/artifacts` 已存在。每次使用新的输出目录，已有目录即使为空也会被拒绝。

```sh
python3 -B -m unittest discover -s tests -v
python3 -B tools/synthetic_pilot.py run --output experiments/artifacts/rc002-demo
python3 -B tools/synthetic_pilot.py verify experiments/artifacts/rc002-demo
python3 -B tools/check_repo.py
```

`run` executes ten trials (two histories × five conditions), writes evidence and a review packet, and never calls a model. `verify` reads data only; it does not execute stored code. A repeated invocation must choose a new directory. Output parents must already exist; symlink paths are rejected. Use a resolved physical path on systems where `/tmp` is a symlink.

## 什么被执行 / What is exercised

The RC-002 seed at `e8350ce` / blob `093e06bd6bc90da68c4cec0172c1a22bff08ecd5` is adapted into the bundled `RC-002-transport-1` fixture. It invents six short events across three session labels, followed by a probe session. Only the reported umbrella location changes between histories. This is scripted history exposure; the confirmation was authored, not generated by the subject. It is not elapsed-time retention, process-restart durability, consolidation, interactive memory formation, or a review of the seed's realism.

| Condition | Exposure | Interpretation |
|---|---|---|
| `current-only` | current probe only | no historical evidence |
| `no-memory` | ordered session history, double configured not to retain across session resets | this double's declared ablation only; not a universal memory-off switch |
| `full-history-in-context` | all case text kept in one session | complete-context control; no search implementation |
| `source-excerpt` | only the historical location sentence | coordinator selects evidence; not native retrieval or an instruction containing a gold answer |
| `scripted-native` | ordered history with explicit session resets | double's in-memory archive persists across synthetic session signals only |

`ScriptedSubject` deliberately recognizes one sentence pattern and answers from admitted text. It is a plumbing double, not a memory system competing in Relata. None of these cells is a CL claim. Missing intermediate evidence in future systems must not be encoded as an automatic failure.

## 观察边界 / Observation boundary

The subject receives only `{operation, text}` messages. It receives neither the world/condition identity nor the fixture object, evaluator contract, scoring diagnostics, review key, or filesystem path. A fresh subject is constructed per trial. Tests place canaries in hidden fields and check that the subject tape is unchanged.

This is an in-process interface boundary, **not a security sandbox**. An arbitrary Python adapter could introspect its caller. The CLI cannot load adapters, commands, providers, or user corpora. Do not mount the complete repository or evaluator artifacts into a future live agent; a separately authorized integration must establish an actual process/filesystem boundary and audit all subject-visible input. No claim of sealed or contamination-proof cases follows from a public fixture.

## Evidence and review

`run.json` binds the implementation hashes, fixture hashes, Python version, randomized plan and execution status. Each `trials/<id>.json` retains its case, condition, ordered subject inputs, attempted/returned states, exact response and literal diagnostics. `summary.json` counts execution statuses and pending reviews; `score` is always null.

`review-packet.json` includes each assigned world's event evidence, governing contract, probe and response under a random alias. It excludes system/condition identity and expected verdicts. `review-key.json` stays with the coordinator. Blinding the case evidence would make identical responses impossible to judge correctly. These fictional materials may reveal their world through the evidence; aliases hide identifiers, not facts needed for judgment.

Do not edit a sealed packet in place. Give reviewers copies and keep their independently completed records separately. This implementation does not import/adjudicate reviewer decisions or compute agreement. Literal location occurrence is diagnostic only: a quotation or negation can contain the correct phrase while violating the task. `semantic_review=pending` and `case_decision=unreviewed` remain unchanged.

## Integrity, errors and recovery

`integrity.json` seals the expected files with SHA-256. Verification also checks planned trial identities, the full two-by-five matrix, case bytes, step order, input views, output binding, diagnostics, summary and review mapping. It rejects missing, extra, reordered, changed or symlinked evidence. Hashes detect changes relative to the seal; they are not signatures, authenticity proof, or proof of actual model execution.

A step is recorded as attempted before invocation. Ordinary execution errors preserve their class without arbitrary exception payloads and do not suppress remaining trials. Keyboard interruption records `interrupted` and leaves later trials `not-run`. An unsealed crash remains incomplete. There is no automatic retry or resume: preserve the directory, then start a fresh attempt. This avoids silently delivering history twice. Files are atomically replaced after file fsync; directory fsync and power-loss guarantees are not claimed.

`run` returns nonzero for interruption or execution errors. `verify` can return zero for a valid evidence bundle that records errors/interruption: inspect its `execution` field. Integrity is separate from execution success and research validity.

The repository checker inventories Git-tracked and nonignored untracked public files. Ignored local records are not opened; force-tracked restricted artifacts and public symlinks fail closed. Links into ignored material do not authorize opening its anchors. No private-artifact scanning mode is added in this change.
