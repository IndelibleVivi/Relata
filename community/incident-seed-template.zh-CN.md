## 1. 当时是什么情境？

只写理解 incident 必需的背景：关系阶段、surface、当时在做什么或处于什么情绪、类似情况以前是否出现过。

## 2. 系统保存了什么，或看起来保存了什么？

可以是事实、summary、style rule、私密称呼、关系状态、model identity，也可以是“完全看不出来”。

## 3. Critical moment 发生了什么？

使用 paraphrase。Raw 或直接可识别的 chat 不得进入本 repo；如果 restricted analysis 确实需要 exact wording，必须在 public repo 之外保存，并另行记录 permission。

## 4. 连续性在哪里断掉，或突然变得特别鲜活？

描述你感受到的 relational effect，不需要把它包装成所有关系都适用的规范。

## 5. 你怀疑问题在哪一层？

可多选，也可以写 unknown：

- ingestion / storage；
- state update；
- authority / perspective；
- retrieval；
- context selection / compression；
- response use；
- correction / repair；
- migration / identity；
- prospective behavior；
- user inspection / control；
- unknown。

## 6. 更好的 behavior region 是什么？

写边界与可能性，不必写唯一“标准答案”。

## 7. 什么内容即使相关，也应该保持沉默？

例如旧伤、未经确认的 inference、只属于另一 surface 的私密语言、第三方说法、已经撤回的习惯。

## 8. 后续 repair 怎样？

系统是否当场接受纠正？之后还会不会再犯？有没有过度补偿成冷淡或僵硬？

## 9. 可公开到什么程度的 architecture context？

只写你舒服的部分：raw archive、memory cards、summary、vector/graph、manual curation、context compiler、model migration，或 unknown。

## 10. 这可能暴露哪一个 Relata distinction？

尽量写成一个可区分的问题，而不是“它记性不好”。

## 11. Limits 与其他合理解释

别人可能怎样理解不同？还缺什么证据？哪些部分只是你的猜测？
