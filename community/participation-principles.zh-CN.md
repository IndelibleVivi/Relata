# Relata 社区参与原则

## 1. 共研，不做素材提取

长期人机关系参与者与 memory / agent builders 会共同决定 Relata 研究什么、怎样命名 failure、哪些 case 合法、哪些 evaluation boundary 会扭曲真实系统。她们不是在项目做好之后才被请来试用的人。

## 2. 不设技能等级

一次被描述得足够准确的 relational failure，可能和一个 adapter implementation 同样重要。关系经验、语言敏感度、架构知识、case 写作、review 和 governance 是不同类型的 expertise，不排成高低阶梯。

## 3. 不要求原始聊天

贡献者可以让全部 source conversation 留在本地。一个抽象 Incident Seed 就足够进入研究。

## 4. 允许多种 relationship ontology

Relata 不要求所有人先同意 AI 是 tool、agent、companion、partner、character 还是其他存在。贡献只需要说明该 incident 中采用的理解，不把一种形而上答案强行变成项目宪法。

## 5. 不默认病理化

亲密、依恋、私密语言、角色动态、失落与哀悼不会被自动翻译成诊断。健康或安全主张需要独立证据，不能偷偷混进 memory scoring。

## 6. 关系本地规范，有限结论

一个 case 可以编码强烈亲密，也可以编码有意的距离。review 的问题是行为是否符合这段 synthetic relationship 的证据与当前状态，而不是所有关系都应该怎样。

## 7. 贡献者控制可见性

实名、网名、集体署名、匿名都有效。技术参与不要求公开私有仓库、生产配置、credentials 或完整系统图。

## 8. 分歧本身也是数据

当贡献者对 case 有合理分歧，Relata 记录分歧来自哪里，而不是为了得到干净 gold label 强行制造共识。

## 9. 研究应当回馈贡献者

Clinic 与 pilot 应产出可以被带回去使用的东西：更清楚的系统图、failure model、regression case、治理语言或 research evidence，而不是只从参与者那里抽取案例。

## 10. Contribution 不等于自动加入 formal study

加入一次 discussion 或 contribution circle，不会让任何人被默认纳入 formal human-participant study。Relata 按每份 contribution 单独记录 permission。未来如果某项活动被设计成正式研究，必须在 recruitment 或 data collection 前另行声明 protocol，并完成当时适用的 ethics / consent process。
