# 参与 Relata

Relata 接受 research、lived-experience、technical、editorial、linguistic、case 与 governance contributions，不要求 coding skill。Source repo 是 public；public-safe code、documentation、source research 与 synthetic-case changes 可以走普通 GitHub contribution。亲密 lived-experience material、identifying consent records 与 restricted system details 不得提交到 public issues 或 pull requests。

Community contributors 以 co-researchers 身份参与。她们可以挑战 project terms、constructs、cases 与 boundaries，而不只是给一套已经固定的 benchmark 提供 examples。

## Contribution routes

### Evidence Card

对 exact public source 与 version 做 close read 或 source-level audit。使用 [Evidence Card template](research/evidence-card-template.md)。

### Incident Seed

对 relational-memory failure 或 continuity moment 提供抽象描述；不要求 raw chat。使用[中文](community/incident-seed-template.zh-CN.md)或 [English](community/incident-seed-template.md) template。

### System Card

用 system-native vocabulary 描述真实 memory / companion architecture，说明哪些内容 observable、opaque、adapter-emulated、unsupported 或 unknown。使用[中文](systems/system-card-template.zh-CN.md)或 [English](systems/system-card-template.md) template。

### Case contribution

提交一张 adult synthetic microcase，包含 bounded construct、counterfactual twin、controls、probe evidence contract、ambiguity analysis 与 privacy declaration。使用[中文 Case Card template](case-lab/case-card-template.zh-CN.md)或 [English template](case-lab/case-card-template.md)。

### Review 或 governance contribution

可以 critique construct、case、reviewer contract、architecture boundary、term、consent route、attribution rule 或 publication boundary。Review 可以不同意 project assumptions，并应保留支持 disagreement 的 evidence。

## R0 contribution process

1. 每份 contribution 单独选择 permission 与 attribution；不要从 group membership 或之前参与中推断。
2. 用 `community/contribution-consent-record-template.zh-CN.md` 在 public repo 外保存 identifying consent record。
3. 只分享能承载 insight 的最小 artifact。
4. 分开 observed / sourced material 与 interpretation。
5. 指明受影响的 Relata question、distinction、assumption、case 或 decision。
6. 至少获得一位不在 original authoring context 中的人的 review。
7. 保持 unresolved disagreement 可见。
8. 只有通过相应 Evidence Card、case review、assumption update 或 decision record，material 才能进入 accepted project authority。

## Privacy

不要包含：

- credentials、tokens、private infrastructure addresses 或 private repo links；
- raw 或可直接识别真实身份的 chat material；
- identifying consent records；
- 未经许可的他人 system 或 relationship details；
- 以 restricted visibility 提供的 private system configuration。

Contributor 可以让全部 source material 留在本地，只提交 abstract Incident Seed 或 public-safe system summary。

Public visibility 不替代 per-contribution permission；本 repo 当前也没有 restricted submission route。

## Attribution 与 review

Contributor 可按 artifact 选择 named、pseudonymous、collective 或 anonymous attribution。Public provenance 应保存 authorship 与 derivation，而不暴露 private source material。若承诺了 pre-publication review，沉默不等于批准。

参见 [consent modes](community/consent-levels.zh-CN.md)、[participation principles](community/participation-principles.zh-CN.md) 与 [attribution / withdrawal](governance/attribution-and-withdrawal.md)。

## Review standard

一份有用的 contribution 会说明：

- exact observed 或 sourced object 是什么；
- 哪些内容是 inference；
- 哪些仍 unknown 或 opaque；
- 哪些 architecture 或 relationship assumptions 塑造了结论；
- 它会改变哪个 project decision、construct 或 case。
