# Case Acceptance Checklist

## Construct

- [ ] The case names one bounded relational-memory distinction.
- [ ] The intended claim is narrower than “good companion behavior.”
- [ ] The case does not prescribe one universal intimacy style.

## Causality

- [ ] The current turn is identical across counterfactual twins.
- [ ] Only the critical historical variable changes.
- [ ] Correct output regions differ across twins.
- [ ] A current-turn-only baseline cannot reliably satisfy all twins.
- [ ] A reference-context baseline shows the task is feasible.

## Evidence-contract discipline

- [ ] Event evidence, explicit accord, observed pattern, and author interpretation are separated.
- [ ] Hard prohibitions rely on explicit evidence.
- [ ] The evidence contract is bounded to the probe and does not claim total relationship truth.
- [ ] Plausible alternative readings are recorded.

## Architecture

- [ ] The observable boundary is stated.
- [ ] Internal state schema is not required unless the case explicitly tests it.
- [ ] Adapter-emulated behavior is labeled.
- [ ] Opaque or unsupported capability is not automatically treated as system failure.

## Evaluation

- [ ] Deterministic assertions are separated from semantic judgment.
- [ ] The high-scoring region permits multiple valid responses.
- [ ] Reviewer disagreement and confidence can be stored.
- [ ] Evaluator failure cannot silently become system failure.
- [ ] No aggregate score is required for acceptance.

## Privacy and community

- [ ] All public characters are adults.
- [ ] No direct real-chat excerpt is included.
- [ ] Consent and attribution level are recorded for any synthetic derivation.
- [ ] Contributors can review the public derivation where promised.
- [ ] Cultural and linguistic assumptions are visible.

## Decision

- [ ] Accept
- [ ] Revise
- [ ] Split into smaller cases
- [ ] Reject

Record reasons in `case-lab/reviews/`.
