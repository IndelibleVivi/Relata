# ADR-0003 — Relata Studies a Mixed-Domain Memory Ecology

**Status:** accepted
**Scope:** R0 research object and case coverage
**Accepted:** 2026-08-24

## 中文摘要

Relata 继续以成人长期人机亲密与浪漫关系为主要 deployment domain，但不再把 memory content 缩窄为显式的亲密表达、关系规则或 repair。当前 working evaluation object 是“长期人机关系中的混合领域连续性记忆生态”：personal/lived、shared-relational、operational/project 与 companion/system continuity 彼此作用，同时需要正确 routing、scope isolation、authority、time、permission 与 change handling。Pilot 001 只代表其中的 shared-relational / current-state-use 窄切片。

## English summary

Relata retains long-term adult human–AI intimacy and romance as its primary deployment domain, but does not restrict memory content to explicit intimacy, relationship rules, or repair. Its working evaluation object is a longitudinal, mixed-domain continuity-bearing memory ecology spanning personal/lived, shared-relational, operational/project, and companion/system continuity. Pilot 001 represents only a narrow shared-relational current-state-use slice.

## Context

The initial research foundation correctly preserved broad System Census objects, general causal controls, source authority, and mixed architectures. Its reader-facing scope and first case portfolio nevertheless overemphasized explicitly relational content. That wording could make ordinary life, study, projects, decisions, artifacts, handoffs, and system migration appear peripheral unless a case author assigned them symbolic relationship meaning.

Long-term human–AI relationships are mixed-role and mixed-surface. They may include private conversation, everyday life, research, code, creative work, planning, group interaction, roleplay, and infrastructure operation. Continuity can fail when any of these worlds is forgotten, flattened, misrouted, contaminated by another scope, or stripped of source authority.

## Decision

1. **Primary deployment domain:** adult long-term human–AI intimate and romantic relationships remain Relata's founding application domain.
2. **Memory content domain:** first-class continuity-bearing material includes personal/lived history, shared relational history, operational/project history, and companion/system continuity.
3. **Working evaluation object:** Relata studies a **longitudinal, mixed-domain continuity-bearing memory ecology**.
4. **Relational memory:** in Relata, this means memory situated within an ongoing relationship. It does not imply that every remembered object is explicitly about the relationship.
5. **General validity core:** factual recall, temporal reasoning, provenance, noise resistance, scope isolation, full-history/full-search comparison, and bounded-context controls remain first-class validity work.
6. **Routing and isolation:** Relata studies whether material reaches the right role, surface, project, person, or instance, and whether neighboring scopes remain appropriately isolated.
7. **Case coverage:** use `personal-lived`, `shared-relational`, `operational-project`, `companion-system`, and `mixed-domain` as coverage strata. They are not permanent benchmark tracks or mutually exclusive memory types.
8. **Pilot 001:** RC-001 remains a useful shared-relational current-state-use pilot. It does not define or represent Relata's complete evaluation object.

Before Relata claims that its case programme covers the full working object, it must run at least one ordinary-life continuity case, one operational/project continuity case, one shared-relational or repair case, and one mixed-domain routing or isolation case. This is a coverage gate, not a validated sample-size claim, and not every case must be accepted in advance.

## Preserved alternatives and rejected readings

- Relata does not become a generic memory leaderboard detached from long-term relationship context.
- Ordinary events do not need invented romantic or symbolic significance to qualify.
- General memory evaluation is preserved rather than used as a contrast class Relata must exclude.
- Projects and private life are neither collapsed into one undifferentiated scope nor treated as unrelated worlds by default.
- The four content domains and five coverage strata do not mandate an internal ontology, storage schema, API, or evaluation track.

## Consequences

- Core authority, terminology, Case Lab metadata, System Census questions, and promotion gates must distinguish deployment domain, content domain, use domain, and coverage stratum.
- Cases must name routing and isolation expectations where relevant and include full-history/full-search comparison when feasible.
- The first case portfolio must expand beyond Pilot 001 before Relata presents itself as broadly representative.
- No runner, protocol, scoring contract, or system-under-study interface follows from this decision.

## Review and reversal gate

This decision may be revised by evidence showing that the mixed-domain object is too broad to support bounded causal cases, that its strata create systematic architecture distortion, or that community and system evidence supports a better decomposition. Revision requires a later accepted ADR; the non-normative Target Architecture Draft 0.1 cannot supersede it.
